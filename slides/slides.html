MODEL

The question

How much does the text to rating relationship vary between products?

  • Not "is there a relationship". There is
  • The interesting part is how much it differs
  • One average number would hide that

70

MODEL · 09_model/model.stan

The model in words

For each review we build one number, called the score, from its 30 components.

score = the average effect of each component
      + how generous this product's reviewers are
      + how strongly THIS product's text predicts its rating

a higher score makes a higher star rating more likely

The third line is what we are here for. It is allowed to differ per product.

71

MODEL · 09_model/model.stan

Why ordinal

  • Stars are ordered: 5 is better than 4
  • But the distance between them is not a real quantity
  • Going 1 to 2 means "still bad". Going 4 to 5 means "actually delighted"
  • Averaging them, as if 3 were exactly halfway, invents a scale nobody used

So the model estimates where the boundaries between stars sit, instead of assuming they are evenly spaced.

72

MODEL · 09_model/model.stan

Why hierarchical

  • 25 products are not 25 unrelated experiments
  • A product with few reviews gets pulled towards the overall pattern, rather than trusting its own thin data
  • And it gives the number we actually want

tau[2] is how much the effect varies between products.

73

MODEL · 09_model/model.stan

Two details in the file

Both are about making the model fit reliably, not about the science.

Written a different waythe same model can be written two ways. One of them makes a shape the fitting algorithm gets stuck in. We use the other
No overall baselinethe star boundaries already set the overall level, so adding a baseline on top would be measuring the same thing twice

Commented line by line in the file if anyone asks.

JOB ARRAYS

Job arrays

The model gave one answer, from one dataset.

  • Collect the data again and the answer would come out slightly different
  • To see how much, take 30 random samples of the data and fit all 30
  • If the 30 answers agree, the result is solid. If they scatter, it is not
  • None of the 30 needs anything from the other 29

So they can run on 30 machines at once.

JOB ARRAYS

What -J does

A .pbs file is an ordinary shell script with a few extra lines at the top saying what hardware it needs. qsub hands it to the scheduler, which runs it on a free machine.

qsub -J 1-30 script.pbs

  ->  the same script started 30 times
      job 1 is told "you are 1", job 2 is told "you are 2"

The script reads that number and uses it to decide which of the 30 samples to fit.

86

JOB ARRAYS · 11_job_arrays/fit_one_replicate.R

How a job knows which one it is

The scheduler puts the number in the environment. R reads it:

from_pbs <- Sys.getenv("PBS_ARRAY_INDEX")
my_number <- as.integer(from_pbs)

That number then sets the random seed, so job 7 always draws the same sample as job 7, on any machine, on any day.

87

JOB ARRAYS

The hard kind, which we avoid

Some problems cannot be split up: every machine needs results from the others as it goes. Weather models and fluid simulations work like that. They use a system called MPI to pass messages between machines, and the code has to be written for it.

Our problem is not like that. The 30 fits never need anything from each other.

So: no MPI, no rewriting. If the task is "do this N times with a different seed", a cluster is already usable.

JOB ARRAYS

Separate output files

These two lines sit at the top of submit_array.pbs, with the other #PBS lines:

#PBS -o logs/rep_^array_index^.out
#PBS -e logs/rep_^array_index^.err

^array_index^ is replaced by each job's own number, so the 30 jobs write 30 separate log files.

Without it they would all write to one file, on top of each other.

CONTAINERS

Singularity

The container system MetaCentrum uses. Also called Apptainer.

  • One image is one .sif file sitting on storage
  • Runs as your own user, not as root
  • Sees your files, so a job reads and writes storage normally
singularity exec -B /storage image.sif Rscript script.R

-B /storage makes the shared filesystem visible inside.

95

CONTAINERS

Why Singularity on a cluster

  • A shared machine cannot hand out root, and Singularity does not need it
  • Files written inside belong to you, not to root
  • An image is a single file, so it lives on normal storage with no service running

Ready made images: /cvmfs/singularity.metacentrum.cz/
